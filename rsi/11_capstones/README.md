# Build, transfer, and explain

[Course](../README.md)

Your final work should be understandable to another student. Give them a task, a runnable system, an honest result, and a clear explanation of its limits.

Use the tools and skills that your experiment needs. A larger architecture is not automatically a better answer.

| Lab | What you will build |
|---|---|
| [11.01 · Build a harness for a new prediction brief](step_01_new_harness/README.md) | A runnable harness that another student can inspect and execute. |
| [11.02 · Run and audit a bounded recursive experiment](step_02_recursive_experiment/README.md) | A solver–improver lineage with matched comparisons and an honest final claim. |
| [11.03 · Test transfer and portability separately](step_03_portability/README.md) | A compatibility matrix backed by actual small runs and clearly marked untested paths. |
| [11.04 · Audit an unfamiliar RSI claim](step_04_external_audit/README.md) | A short primary-source audit with a concrete follow-up experiment. |
| [11.05 · Teach the mechanism and defend the evidence](step_05_teach_back/README.md) | A concise portfolio that a peer can run, question, and understand. |

Start with the first lab and follow its next link. Each lab keeps its notes in a separate workspace and links any earlier experiment it reuses. The agent writes code; you predict, inspect, and explain. [Skill entry point](../skills/rsi-tutor/SKILL.md).

Keep the portfolio small enough to inspect and complete enough to reproduce. A well-explained failure can be a strong final project.
