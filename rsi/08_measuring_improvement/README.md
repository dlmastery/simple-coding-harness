# Measure what improved

[Course](../README.md)

A better score can come from a better method, more attempts, easier data, or an evaluation mistake. Design comparisons that separate those explanations.

Use the fixed and modified skills from earlier themes. Freeze the comparison before reading its result.

| Lab | What you will build |
|---|---|
| [08.01 · Distinguish a result from a reliable comparison](step_01_repeat_measurement/README.md) | A repeated comparison with paired seeds and an explicit uncertainty statement. |
| [08.02 · Freeze selection before final evaluation](step_02_final_boundary/README.md) | A selected recipe evaluated once on the final public partition, with further search closed. |
| [08.03 · Count the cost of research](step_03_cost/README.md) | A resource ledger that includes proposals, checks, retries, failed work, and fitting. |
| [08.04 · Separate the effects of memory and procedure changes](step_04_ablation/README.md) | A small factorial comparison of memory and a task-skill revision. |
| [08.05 · Test whether the lesson transfers](step_05_transfer/README.md) | A transfer report that applies a frozen research skill to wine classification. |
| [08.06 · Reject a misleading win and roll back](step_06_rollback/README.md) | A promotion decision that rejects a superficially strong but invalid candidate. |

Start with the first lab and follow its next link. Each lab keeps its notes in a separate workspace and links any earlier experiment it reuses. The agent writes code; you predict, inspect, and explain. [Skill entry point](../skills/rsi-tutor/SKILL.md).

You can now ask a sharper recursive question: does the changed procedure produce better future improvements?
