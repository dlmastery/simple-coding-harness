## Frozen skill comparison

Both skills start with the constant model using the task's permitted inputs. Both receive two fits. The parent chooses tree on its second attempt. The child computes the largest and smallest mean absolute baseline residual across predeclared groups. If the ratio is at least 1.5, choose linear; otherwise choose tree. If the smallest mean is zero and the largest is positive, use an infinite ratio; if both are zero, use ratio 1. Retain the better candidate by the declared task metric.

Bike groups are recorded hours; all recipes use calendar features. For wine, use alcohol quartiles with cutpoints calculated from training features only; the absolute binary residual is the misclassification indicator. All wine physicochemical inputs remain available to both recipes. The interface map is fixed before the new wine fits. It does not establish that this diagnosis is scientifically optimal: ordinary error slices may weight classes differently from balanced accuracy. Keep that potential mismatch visible.

Only the second-choice rule changes between task skills. The author implements these exact Markdown rules through a constrained interpreter, not a general natural-language execution engine. The canonical improve-research-skill procedure supplies the fixed author workflow; its bytes must be unchanged at the end. The author proposes the edit. This demonstrates a controlled skill change, not autonomous invention or recursive improvement.

## Replayed evidence and limits

For the two reflection checks, recompute training and selection metrics from the saved synthetic predictions and verify their source rows and targets. Use no final metrics to select a rule. The narrow lesson is to compare on the declared selection metric for comparable candidates, rather than promoting solely on training fit or model-family slogans. Selection itself can overfit; these cases do not eliminate that risk.

For retained memory, choose between checked public wine majority and linear predictions. A deliberately weak no-memory control minimizes a raw numeric score without respecting metric direction. The memory-aware procedure reads the task's direction and selects accordingly. This makes use of the saved rule inspectable; it does not measure how well an LLM learns or generalizes. Scope requires identical task, data role, metric, and candidate-validity checks. Reject a comparison outside that scope.

For modification, two labelled input reports share the same pinned baseline predictions: one correct and one wrong. The fixed external evaluator checks whether the reported value equals recomputed MAE. Compare both skill versions on both reports; retain the child only if it introduces no failure and repairs the wrong report. Record each version read at execution.

For the memory ablation, effects are differences in cached balanced accuracy. The restrictive memory may be neutral for the parent and harmful for the child. Retain the interaction rather than claiming that adding components always helps. Removing the rule creates a fifth follow-up result, not a replacement arm.

No learner participates: predictions, quiz responses, and teach-back stay unattempted. The supplied source and selection partitions are public. Do not claim evaluator secrecy, a fresh native coding agent, weight learning, unseen transfer, or general improvement from this run. Account for implementation and inference costs as unknown when not metered.
