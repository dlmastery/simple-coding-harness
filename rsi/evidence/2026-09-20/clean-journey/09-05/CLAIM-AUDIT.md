# What this comparison supports

**Supported:** an author-guided revision to a skill-promotion procedure is read and applied in later improvement work. Its implemented selection gate changes the regression decision and prevents the observed final loss in this constructed case. Both procedures retain the useful classification edit. Eight fits and their costs remain visible.

**Fixed:** data, partitions, metric, model settings, initial task skill, candidate task-skill edit, fit allowance, and final-scoring procedure. **Changed:** the partition used by the improver to promote a task-skill proposal. **Feedback:** measured predictions, plus author-supplied diagnostic fixtures and revision. **Persistence:** two versioned Markdown procedures, recorded hashes, and later decision traces. **Promotion authority:** the generated driver implements the selected procedure's declared rule.

The regression loss under v0 is preserved; it is not omitted from the result. V1's unchanged solver is counted as zero gain, not a new solver improvement. There is no cross-task average because MAE and balanced accuracy have different meanings and units.

**Missing:** independent coding-agent contexts, autonomous proposals or improver revisions, more task families and seeds, strong competing improvers, privately controlled evaluation, complete service costs, multiple recursive generations, learner validation, and acceleration evidence. No claim is made that all of theme 09 was executed. The new run exercises the matched comparison in 09.05 and the version/use distinctions in 09.01, 09.03, 09.04, and 09.07. Earlier inheritance fixtures remain separate evidence.

**Counterexample:** selection feedback can be noisy or repeatedly overused. A rule can select a child with slightly better selection performance and worse final performance. This comparison does not rule that out.

**Smallest useful next experiment:** freeze these exact procedures and allocate the same candidate budget to independently prepared tasks and additional seeds. Include a stronger improver and retain all decisions. Use separate agent contexts if the host provides them; measure proposal and review costs as well as fits. Do not reuse these observed final cases to select a revised gate and then label them fresh tests.
