# A null effect with a concrete explanation

All valid proposals reached the fit stub. The leaked proposal was blocked in both main arms. Removing the domain check alone made no difference because the tool allowlist still rejected casual. In the separate additional ablation, removing both allowed the leaked input to reach the stub.

The main result does not show that domain knowledge is useless. Two guards overlap on this one fixture. The follow-up demonstrates dependence on their combined protection, not each guard's isolated contribution across arbitrary failures. No leaked model was trained and no prediction-quality improvement was measured.
