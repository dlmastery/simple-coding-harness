# Workflow and recovery

1. Read the brief and inspect the pinned data card. Confirm the retrospective prediction setting.
2. Create a fresh learner workspace and record the generated wrapper identity.
3. Let the shared runner verify data, task contract, remaining attempts, and active lock.
4. Reserve the attempt before fitting. Use training-only preprocessing and the fixed partition.
5. Save predictions and the result. Recompute the metric from pinned targets and compare the ledger and report.
6. Report the checked score or concrete failure. Stop at two admitted attempts.

The brief supplies target, data, split, metric, leakage exclusions, budget, and required evidence. The builder chose this thin wrapper around existing tools, command arguments, and output structure. The running harness admits or refuses a request and checks its result. It does not choose new research hypotheses itself.

For an interrupted process, inspect the actual process and shared-runner lock. Preserve the failed or interrupted attempt. Follow the course recovery rules before any retry. For changed code or scientific requirements, use a new workspace. Do not erase the old result or refund an attempt.

The observed refusal checks belong to this package and these cases. They do not demonstrate arbitrary agent isolation or GPU support.
