# Experience becomes a frozen research rule

The actor compiled all 96 checked development attempts into a persistent
experience store. It retained source generations and outcomes instead of only
the winners. The [memory note](MEMORY.md) explains its interpretation;
[experience rows](EXPERIENCE.csv) and [input identities](INPUT-IDENTITIES.csv)
show its evidence. Passing numerical checks does not certify a causal lesson.

Three retrieval weights were compared in six leave-one-development-task-out
replays. Each replay chooses eight recorded candidates, using only two
same-kind peers to rank its later choices. There are **144 lookups and zero
new fits**. All **213 independent checks pass**. Fourteen original files are
preserved with [matching bytes](ARCHIVE-MANIFEST.csv).

The outcome ties. The declared rule therefore retains **alpha zero**, the
simple global-rank memory. Do not present extra retrieval complexity as a
measured gain. Inspect [the choices and revealed outcomes](REPLAY-TRACE.csv),
[summary](REPLAY-SUMMARY.csv) and [selected policy](SELECTED-POLICY.md).

The retrieval weight was selected on development outcomes. It still needs
later task evaluation. This finite recorded-candidate replay is a control,
not a reproduction of Dream-RSI's full simulator or branching mechanism.
The [earlier discovery-tree study](../discovery-final/README.md) retains that
separate evidence and its actual reduction in executed fits.

The next comparison must use budgets smaller than the useful proposal space,
preserve source-level harness changes and demonstrate later inherited-updater
use. Reordering and exhausting one shared list would repeat the original
course's mistake. See [the implementation design](../../../../how-did-i-generate-it/rsi/validation/REAL-TABULAR-COMPARISON-DESIGN.md).
