# Ask what a category requires

Selected definitions read on 21 September. The [framework](https://arxiv.org/html/2609.11873v2) first appeared 10 September; v2 is dated 15 September. Initial inspection used v1, followed by a check of the relevant v2 definitions. This report uses v2, not an undated blend.

| Framework criterion | Required observation |
|---|---|
| B0, §3.1: task-local refinement | Changed output without persistent system adaptation across independent tasks |
| L1, §3.2.7: execute specified improvement procedures | Execution record and retained development artifacts |
| L2, §3.3: choose interventions from feedback | Evidence-to-next-intervention decision |
| L3, §3.4: guide future learning experience | Learned state changes later acquisition decisions |
| L4, §3.5: retain operational adaptation | Deployment feedback produces persistent changes used later |
| Structural L5, §3.6 | Revised improvement mechanism governs a later round |
| Effective L5, §3.6 | That mechanism yields better successors in a fair independent comparison |

[Weco's framework](https://www.weco.ai/blog/4-levels-of-recursive-self-improvement), 10 July 2026, instead emphasizes outcomes. Level 0 delegates research but trails human efficiency. Level 1 requires a fair human baseline, sustained gains, transfer, and fixed resources. Level 2 adds a demonstrated better improver. Level 3 requires rising gains at fixed effort. These are historical, source-specific definitions, not matching numbers for the table above.

Apply both sets to [the actual cases](THREE-CASES.md). A missing criterion stays unsupported.
