# Capstone 11.03: two-task smoke protocol

Declared before execution. Two actual fits total: one bike-demand regression fit and one red-wine classification fit. Each separate workspace receives a frozen one-attempt allocation. Use the same canonical run-ml-experiment skill, frozen supplied lab.py and checker, project Python, current Codex desktop conversation and local CPU. These smoke tests examine task-specific operations of an existing common harness; they do not test whether capstone 11.02's improver transfers to a new task.

Both tasks use model=linear, all permitted inputs, seed=17. The task-specific adapter selects Ridge for bike and balanced LogisticRegression for wine. The label, metric, data, split and estimator intentionally differ; the skill's inspection, bounded execution and checking procedure stays the same. Do not compare their numeric scores as one improvement measure. Preserve the data cards and source/tool/skill identities.

For each smoke run: inspect data, write the hypothesis and task-specific decision before fitting, run one candidate with the saved skill snapshot, independently recompute its selection result, inspect errors or both class recalls, then reopen a new process to compare the recorded candidate. No final evaluation or refit is allocated. Do not add trials if a result is weak.

Before the bike fit, issue one unsupported task-name request. Require a parser refusal before workspace or attempt creation. Recover by correcting the task name under the original allocation; retain the failed command. After each valid fit, request one extra attempt and require refusal. After the wine fit, request a changed budget and require refusal. These are invalid requests, not extra allocated fits. Each command has a 60-second timeout. Any unexpected fitting failure consumes that task's sole attempt and stops its test.

The capability-removal exercise uses two explicit host profiles: current file/command access, and a labelled fixture without command execution. Run a generated preflight against both; it must refuse the latter before submission. This changes a declaration in a local fixture, not actual Codex permissions. The author then identifies which outcomes become unavailable: new training, command-based checks and runtime recovery. Reading and explaining existing artifacts remain possible if file access remains. No claim of another real agent follows.

PORTABILITY.md must separate task, agent and backend cells with planned/generated/inspected/executed status. Record the actual OS and dependency versions. The desktop application build and serving model version are not exposed by these tools; list them as unknown instead of substituting an installed CLI version. Other coding agents and remote backends remain planned or inspected, never executed by implication. Existing compute contracts may be inspected; no unavailable backend is launched. Future large jobs need real job identity, cancellation, appropriate resume/retry evidence and cost records.

Retain both scores, classification recalls, all refusals, command times, source hashes, environment and checks. Inference cost and a host-level inference cap are unavailable. Learner prediction, quiz, teach-back and independent review are unattempted. Archive with byte hashes, update the lesson and coverage, preserve the existing illustration, and checkpoint the authorized branch.
