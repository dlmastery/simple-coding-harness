# What the recorded comparison supports

The strongest supported claim is a bounded, author-guided demonstration: a revised promotion procedure is read and applied in later improvement work. In the constructed regression case it avoids the loss caused by the weaker rule; in the classification case both retain the useful child. See the original [claim audit](../../../../rsi/evidence/2026-09-20/clean-journey/09-05/CLAIM-AUDIT.md) and [results](../../../../rsi/evidence/2026-09-20/clean-journey/09-05/FINAL-RESULTS.csv).

| Claim | Evidence and limit |
|---|---|
| Structural recursion | Changed improver identity plus a later action governed by its rule. Author-supplied versions and a restricted interpreter bound this demonstration. |
| Benefit on the tested cases | Matched prediction bytes and different retention on regression. Avoiding a loss is not an improvement over the original solver. Both arms retain the same useful classification child. |
| Equal total research cost | Not established. Fit allowances match; inference and authoring costs are unavailable. |
| Autonomous improvement or general transfer | Not established. Shared author context, fixed proposals, two constructed cases and one split per task leave these questions open. |
| Sustained acceleration | Not established. There is no multi-generation rate estimate with complete resource accounting. |

A plausible weaker explanation is that a simple, author-chosen selection gate corrects an intentionally weak control. This is consistent with the measured result. A useful next experiment freezes the procedures and tests independently prepared tasks against a stronger improver, with all costs retained. Do not use these observed final cases to select the next rule and call them fresh evidence.

## Three teaching cases

These are author answer notes. Learner predictions, answers and teach-back remain **unattempted**.

- Repeated model search: the recipe or model changes while the search procedure stays fixed. Repetition and a rising score do not establish an inherited improver revision.
- Persistent memory under a fixed updater: future work reads retained state. Use and benefit need evidence; the unchanged updater does not become recursive merely because it writes more memory.
- An inherited improver that loses a matched comparison: structure may be established while benefit fails. Preserve the loss, restore the accepted active version when the protocol requires it, and do not relabel the outcome as acceleration.

## Remove the inheritance evidence

Consider a labelled evidence subset that retains only final predictions and scores. Exclude the procedure files, before-action records, applied-rule decisions and any summaries that disclose them. The task score can still be checked. Which procedure produced or selected it can no longer be established from that subset, so structural recursion is unsupported there. A high score does not restore the missing causal chain.

This is an evidence-removal analysis, not destruction of source files. Merely hiding one trace while leaving equivalent identity and decision evidence elsewhere would not necessarily remove support. All original artifacts remain available through this review.
