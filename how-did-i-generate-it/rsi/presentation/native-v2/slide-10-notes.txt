Teaching point: A result depends on the correct data, code and earlier decisions.A graph makes dependencies explicit. If an input changes,some descendants need new evidence. A table that combines scores from differentdatasets can look convincing while answering no valid comparison. Follow onedependency and ask which hash or record establishes that it is the intendedinput. Graph completeness also matters: an omitted edge can hide a requirement.Source: theme 03 and graph-reconciliation evidence.Course evidence and reading:https://github.com/dlmastery/simple-coding-harness/blob/7db77bd8d38aa5f23dc4180e341de415d6b99296/rsi/03_graph_engineering/README.mdhttps://github.com/dlmastery/simple-coding-harness/blob/7db77bd8d38aa5f23dc4180e341de415d6b99296/rsi/evidence/2026-09-22/graph-reconciliation/README.mdIllustration: https://github.com/dlmastery/simple-coding-harness/blob/7db77bd8d38aa5f23dc4180e341de415d6b99296/rsi/assets/illustrations/artifact-dependencies-v2.pngThe figure explains a mechanism.
