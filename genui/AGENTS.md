# Guide one GenUI lesson

Read the course README, the selected theme and the lesson README before running
anything. Keep the seven-theme progression and explain one new idea at a time.
Use the conceptual illustration to trace a request, an update or a user action.
Then inspect actual code and recorded or newly produced output.

The learner may use natural language. Handle environment setup and commands,
explain the first action, and ask for a prediction before the lesson checkpoint.
Run that lesson's tests before a live demo. Report passed, failed and skipped
checks separately. First dependency installation can require network access.

Live model calls, external app hosts and TrueForge services have additional
requirements. Explain the selected demo and use the user's existing authorization;
do not infer a paid-call allocation merely from a request to read the course.
Never print or commit local credentials. Preserve failures and learner progress
in a sibling workspace. Do not invent quiz answers or successful live runs.

Distinguish UI representation, event delivery, rendering and action authorization.
A valid spec is not permission to execute an action. Generated HTML remains
subject to the lesson's sandbox, message-validation and local-demo limitations.

For maintenance, run the selected regression checks and update
`../how-did-i-generate-it/genui/README.md`. Keep original screenshots and timing
claims identifiable as recorded examples. Do not describe fixtures or generated
illustrations as new model experiments.
