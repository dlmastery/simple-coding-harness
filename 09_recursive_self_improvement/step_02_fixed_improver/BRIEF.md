# Lab 09.02 brief

Two generations of task-skill revision governed by one fixed improver.

Starting state: A parent task skill, one fixed improver version, and development cases.

Prediction to ask: Can the solver improve twice without the improver improving at all?

Execution limit: Two generations, at most two fits per generation. Include proposal and checking costs.

Follow the README steps. Keep source data and the supplied evaluation contract unchanged. Use the canonical course skills. Generate any required code yourself. Save observations, failures, and the learner’s progress in the separate workspace. Do not invent student answers, measurements, or protected evaluator access.

Acceptance: Both rounds use the same improver. Every retained task skill has a corresponding evaluation. The conclusion says repeated self-improvement, not automatically RSI.
